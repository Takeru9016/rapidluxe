# RapidLuxe 2.0 — Journeys Listing

**Priority:** P1

## Purpose

Turn the existing package listing into an editorial Journey-discovery experience while keeping Package as the backend entity.

## Requirements

- Hero and search/discovery input.
- Filters: destination, duration, budget, travel intent/style, season and useful package attributes.
- Cards: image, Journey name, destination, duration, starting price, experience tags, wishlist and request CTA.
- Sorting: relevance, price, duration, curated/newest.
- Do not restore fake rating-based sorting.
- Strong loading, empty and error states.

## Review

**HIGH PRIORITY.** This is the most visible place to introduce Journey terminology. Existing API/filter infrastructure can support it.
